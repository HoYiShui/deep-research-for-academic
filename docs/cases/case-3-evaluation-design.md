# 双输出内部威胁检测方法的实验协议设计（检测 / 溯源 / 泛化）

## 0. Research Brief

- **研究类型**：evaluation_design
- **要解决的决策**：为「用户风险分数 + 事件排序」方法，设计分别验证**检测 / 溯源 / 泛化**三主张的协议，并界定每个协议的结论边界
- **研究对象与范围**：CERT r4.2/r6.2；时间切分、未见用户、跨版本迁移；有限算力
- **结论边界**：明确每个协议「能支持 / 不能支持」的结论；不承诺生产效果
- **关键假设**：answer 事件级真值可用（前置待核实）；双输出同源

## 1. 问题定义与研究边界

### 1.1 目标问题

一个同时输出「用户风险分数」（检测）和「事件排序」（溯源）的方法，实际上提出的是**三个不同性质、需要不同证据**的主张：
- **检测主张**：用户级风险分数能把内鬼与正常用户区分开；
- **溯源主张**：事件排序能把真正的恶意事件排到前列，供分析员定位；
- **泛化主张**：上述能力在（a）时间前移、（b）未见用户、（c）跨数据集版本时不被破坏。

三者**不可用同一指标、同一协议糊在一起**——例如 AUC 高不代表事件定位准，用户级告警预算达标不代表跨版本迁移成立。本节目标就是把三主张拆成可分别证伪的协议。

### 1.2 系统、数据与威胁边界

- 数据：CERT r4.2（1000 用户/70 内鬼/3 场景/~32.77M 事件）与 r6.2（4000 用户/5 内鬼/5 场景/~135.1M 事件）。
- 标签粒度：默认 **user-day**；事件级真值以 `answer/` 文件场景描述 + 涉及文件/时间窗形式**部分**存在（**粒度待核实，是溯源协议的第一前置项**）。
- 威胁类型：数据窃取 / 知识产权盗取 / IT 破坏 /（r5.2+）横向移动。
- 极端不平衡：r6.2 为 5/4000（事件级可低至 10⁻⁶）。

### 1.3 本报告不回答的问题

- 不给具体实现或超参；不保证生产部署效果；不回答「若无事件级真值时」的替代标注方案细节（仅在 §3.4 给出原则）。

## 2. 证据基础与关键发现

### 2.1 检索范围与信源标准

同 case-1/2：同行评议论文 > 综述 > 数据集文档 > 灰文献。重点检索「切分协议先例」「事件定位指标」「校准/告警预算」三类。

### 2.2 已确认事实（含来源定位）

**切分协议先例**

1. **时间切分 + buffer 区防泄漏**：一篇用 CERT 场景结构做受控实验的工作（arXiv:2602.11019）给出标准时间切分：对每个恶意用户攻击区间 `[t_start, t_end)`，设 buffer `Δ_buf=168h`（1 周）；`normal-before`（`<t_start−Δ_buf`）与 `normal-after`（`>t_end+Δ_buf`）进入训练/正常测试，攻击窗口仅入测试集，两侧 buffer 全剔除；正常数据再按 `ρ=0.8` 时间序切分（早 80% 训练、后 20% 测正常重建）。窗口 `Δ_w` 常用 24/48/96h。
2. **未见用户切分**：按 user 分组 70/15/15（train/val/test）防身份级泄漏；另有 CNS20 工作显示训练集用户数与时长影响性能（含恶意用户混入训练会毒化 AE）。
3. **阈值按目标 FPR 选取**：以「最高阈值且 FPR≤目标」定阈值（如 r5.2 目标 FPR=0.05、r6.2=0.09，因 r6.2 ROC 更低）；一篇 TNSM 工作报 r6.2 场景 1/3/4 在 0%–0.04% FPR 可检出，场景 2/5 需 3.07%/8.36% FPR（场景难度不均）。
4. **跨版本迁移先例**：r4.2 训练 → r6.2 测试作鲁棒性检查；一个「百分位表示」方法 r4.2→r6.2 UAUC=0.908（原表示仅 0.511）；一篇 XGBoost 研究报 r6.2 默认阈值下 F1=0.0000（正例预测为空）而 AUC=0.9725（校准失效）。
5. **跨版本评测专用集**：TRACE-IT（IEEE DataPort, DOI 10.21227/bdg8-0565）从 r4.2/r5.2/r6.2 派生用户级特征（109/108/108 维），建议 user-grouped 验证 + 报告 Macro F1 / balanced accuracy / ROC-AUC / ECE / Brier。

**指标先例**

6. **检测指标**：ROC-AUC、PR-AUC（不平衡下更严）、Macro F1、balanced accuracy、DR/TPR、用户级 FPR（UFPR）、检测延迟（DD）。
7. **告警预算**：在固定告警量下报 precision/recall（如 top-100/1000 用户），而非仅 AUC；有工作报「recall 1.0 但 precision 0.004」的极端案例（r6.2 5 内鬼）。
8. **事件定位指标**：无标准 hit@k；相近做法是**基于重叠/IoU 的 range-based P/R/F1**、时间容忍 F-score（容差半径 d）、IoU>θ 贪心匹配（每个真值/预测至多用一次，未配对的预测=FP、未配对真值=FN）。要点：**对区间结构用 range 而非 point 打分**。
9. **校准指标**：ECE、Brier（可分解 REL−RES+UNC），用于判断「分数能否被阈值化」——这是「面向分析员」告警可行动的前提。

### 2.3 研究论断与证据缺口

| 论断 | 证据定位 | 关系 |
|---|---|---|
| C1「检测、溯源、泛化需不同协议/指标」 | 多源（不平衡指标 + 事件定位 + 迁移各自独立） | **supports** |
| C2「随机切分会夸大性能、掩盖不平衡」 | 综述 + SIEM 原型 + 时间/用户切分先例 | **supports** |
| C3「r6.2 存在校准失效（默认阈值零正例）」 | XGBoost 研究（F1=0 vs AUC=0.9725） | **supports**（单篇） |
| C4「跨版本迁移退化是真实的」 | r4.2→r6.2 UAUC 0.908 vs 0.511；XGBoost 退化 | **supports**（单篇/多源） |
| C5「事件级真值可用以支撑溯源协议」 | `answer/` 含场景+文件+时间窗，但**粒度未核实** | **partial**（前置未确认） |
| C6「告警预算/校准比裸 AUC 更贴近分析员」 | SIEM 原型 + 综述 + 告警预算文献 | **supports** |

**关键证据缺口**：`answer/` 事件级粒度未确认（决定溯源协议的指标形态）；缺「同一方法三主张同时评估」的先例（即本方案的增量）。

## 3. 验证方案设计

### 3.1 研究论断（三主张）

- **P1（检测）**：用户风险分数在「未见用户 + 时间前移」下，以**告警预算召回/PR-AUC**衡量，显著优于无信息基线（随机/IF/OCSVM），并在同一预算下接近或达到强监督树基线（XGBoost）。
- **P2（溯源）**：事件排序在**攻击窗口内**的事件级定位命中（hit@k / 重叠 recall@k）显著高于「按风险分数均匀降序的朴素事件排序」与「随机排序」；且事件排序不牺牲 P1 的检测指标。
- **P3（泛化）**：检测与溯源能力在**跨版本迁移（r4.2→r6.2 及反向）**下的退化**显著小于**「无领域适应/无校准的同一模型」这一对照，并可用校准（ECE/Brier）+ 阈值适配部分恢复。

### 3.2 数据集、切分与基线

**数据与切分（统一防泄漏框架）**

- 时间切分：采用 §2.2 先例——对每个恶意用户设 `Δ_buf=168h` buffer，攻击窗口仅入测试；正常数据按 `ρ=0.8` 时间序切分（早 80% 训练 / 后 20% 测正常）。窗口 `Δ_w ∈ {24, 48, 96}h`。
- 未见用户切分：**用户级 disjoint** 的 70/15/15（train/val/test）；恶意用户**永不入训练/验证**（关键：杜绝「把内鬼学成正常」的毒化，CNS20 已示警）。
- 跨版本迁移：**A→B**（r4.2 训练 → r6.2 测试）与 **B→A**（r6.2 训练 → r4.2 测试）两组；特征空间须对齐（可参照 TRACE-IT 的 109/108 维对齐方案，或自建同构特征）。

**基线（按主张分层）**

| 主张 | 强基线 | 弱基线（下限） |
|---|---|---|
| P1 检测 | XGBoost/LightGBM（会话特征）、RMSL（弱监督） | Isolation Forest、OCSVM、随机 |
| P2 溯源 | 注意力权重 top-k（时序/图黑箱的定位代理）、RMSL 行为级分数 | 均匀降序、随机排序 |
| P3 泛化 | 「无校准的同一模型」直接迁移 | 在目标版本重训（oracle 上限） |

### 3.3 协议—指标—结论映射

| 主张 | 实验协议 | 对照组 | 指标 | 能支持的结论 | 不能支持的结论 |
|---|---|---|---|---|---|
| **P1 检测** | 时间切分 + 未见用户切分；r4.2 与 r6.2 各自独立评测；固定告警预算（如 top-100/1000 用户） | 随机/IF/OCSVM（下限）、XGBoost/RMSL（强基线） | PR-AUC、ROC-AUC、告警预算下 precision@k/recall@k、Macro F1、balanced accuracy、UFPR、检测延迟 | 「方法在时间前移+未见用户下能区分内鬼，且不劣于强基线」；「告警预算下的可行动性」 | 「生产环境绝对检测率」；「跨版本泛化」（需 P3 协议）；「事件定位」（需 P2 协议）；「分数校准可信」（需 P3 的 ECE/Brier） |
| **P2 溯源** | 在**已判定为威胁用户**的攻击窗口内，对事件排序打分；`answer/` 真值作 ground truth | 均匀降序、随机排序（下限）；注意力 top-k、RMSL 行为级分数（强基线） | 事件级 hit@k、重叠/range-based recall@k/precision@k、IoU>θ 匹配 F1、时间容忍 F-score | 「事件排序能把真实恶意事件排前，优于朴素/随机排序」；「双输出不牺牲检测（联合报 P1 指标）」 | 「事件真值之外的威胁类型」（限于 CERT 场景）；「排序的因果正确性」（只证相关定位，不证因果关系）；「若 answer 仅 user-day 级则 P2 需退化为攻击窗口内命中代理」 |
| **P3 泛化** | ① 时间前移（早→晚）；② 未见用户；③ 跨版本 A→B / B→A 迁移；均复用 P1/P2 指标 | 「无校准同模型」直接迁移（对照）；目标版本重训（oracle 上限） | P1 指标 + P2 指标的**跨域退化差（Δ）**、ECE、Brier（REL−RES+UNC）、校准后告警预算召回 | 「泛化退化可量化，且校准/领域适应能部分恢复」；「退化来自校准而非纯容量」（结合 Brier 分解） | 「零退化泛化」；「退化原因的唯一归因」（需消融，见 §3.4）；「真实企业环境的泛化」 |

### 3.4 失败模式与补实验方案

| 失败模式 | 征兆 | 补实验/修正 |
|---|---|---|
| `answer/` 无事件级真值（仅 user-day） | P2 无法算 hit@k/事件重叠 | 退化 P2 为「攻击窗口内事件排序命中」代理：top-k 事件是否落在 `[t_start,t_end)` 且活动类型匹配（file/device/email 等）；并显式声明为代理指标 |
| r6.2 默认阈值零正例（校准失效） | P1/P3 在 r6.2 上 precision/recall=0 而 AUC 高 | 强制报告 ECE/Brier + 校准后告警预算召回；把「校准」作为 P3 显式实验臂 |
| 时间切分 vs 未见用户切分结论相反 | 两协议 Δ 不同 | 分别报告并归因：时间漂移 vs 用户异质性；补 LOEO（leave-one-entity-out）与时间窗 rolling 对照 |
| 场景难度不均（r6.2 场景 2/5 极难） | 总体指标被难场景拉低 | 分场景报告（per-scenario），并把「少数场景可靠性」列为独立指标（TRACE-IT 亦建议） |
| 跨版本退化被归因错误（不平衡 vs 漂移） | P3 只报 Δ 不报分解 | 用 Brier 分解（REL−RES+UNC）+ 「同模型换特征 vs 同特征换模型」消融，区分容量/校准/分布漂移 |
| 事件排序与检测耦合、难以单独归因 | P2 提升伴随 P1 下降 | 联合报 P1+P2，做「固定检测预算下的事件命中」曲线（Pareto），而非单点 |

## 4. 可支持的结论与建议

### 4.1 证据支持的结论

1. 检测、溯源、泛化是**三类不同主张**，需**三套协议 + 三套指标**分别证伪，不能用单一 AUC 覆盖。
2. **随机切分会系统性夸大性能**，须用「时间切分（含 buffer 防泄漏）+ 未见用户切分」作为检测主张的最低协议门槛。
3. **r6.2 的校准失效是已知陷阱**（默认阈值零正例而 AUC 高），P3 必须显式纳入 ECE/Brier 与校准。
4. 事件定位没有统一指标，**应使用区间/重叠类指标（range-based P/R/F1、IoU 匹配、时间容忍 F-score）**而非 point 精确匹配。

### 4.2 适用前提与残余风险

- **溯源协议的前提未锁定**：`answer/` 事件级粒度未核实，是 P2 的硬前置；未核实前，所有「事件级 hit@k」都只是代理。
- **r6.2 样本量极小（5 内鬼）**：统计显著性弱，P1/P3 在 r6.2 上的结论应附置信区间/多次种子，避免把「5 个内鬼的一次运气」当结论。
- **合成性外推**：三主张结论仅在公开 CERT 基准下成立，不外推到真实企业日志。
- **跨版本特征对齐**：r4.2/r6.2 特征空间不同（事件类型/规模），迁移实验须明确对齐方案，否则 Δ 含「特征不对齐」噪声。

### 4.3 下一步行动建议

1. **第一前置动作**：下载解析 `answer/` 文件，确认事件级真值粒度，据此最终锁定 P2 指标形态（真实事件级 hit@k 还是窗口内命中代理）。
2. **先跑 P1（检测）+ 时间/未见用户切分**（最便宜、结论最硬），再上 P3（跨版本 + 校准），最后 P2（溯源，依赖前置）。
3. 用本报告的「协议-指标-结论映射」作为实现验收清单，逐行核对「能支持/不能支持」。

### ⚠️ 发现的问题

1. **「r6.2 F1=0.0000 / AUC 0.9725」归错论文（同 case-1）**：该结论来自 **Grid Search + SMOTE** 的 XGBoost 研究，而非本报告引用的 **Bayesian-Optimized XGBoost（spy2.70122）**。影响 §2.2 #4、C3、参考 #6。
2. **「时间切分 + buffer 协议（Δ_buf=168h、ρ=0.8、窗口 24/48/96h）」归到 arXiv:2602.11019 存疑**：检索到的该文内容为「信号分解 / activity presence vs magnitude 双通道自编码器、以 PR-AUC 为主指标」，未提及这些 buffer/切分参数。可能归错了来源，或这些参数藏于该文方法节，需回原文核实。
3. **「百分位表示 r4.2→r6.2 UAUC=0.908（原表示 0.511）」无出处**：§2.2 #4 与参考 #7 均未给出论文名/DOI/arXiv，检索也未找到该数值。这是本 case 最薄弱的一条「跨版本鲁棒性先例」，建议补确切来源或降级为「待核实」。
