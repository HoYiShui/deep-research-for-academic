# Deep Research for Academic — 网络安全学术研究 Multi-agent Deep Research 系统 章程

面向网络空间安全学术研究人员的 Multi-agent Deep Research 系统，用于学术选题、技术
路线对比与验证设计，最终交付可部署系统。本章程为项目最高治理文档，约束 Agent 行为
与工程实践；系统功能需求由 `/speckit-specify` 定义，不在此重复。

## 核心原则

### I. 真实性与可溯源（不可协商）

Agent 在交互与产出中的任何文献引用、数据点或结论 MUST 真实且可溯源。

- MUST NOT 生成无法验证或不存在的文献引用（幻觉引用）。
- 无法溯源的内容 MUST 显式标注「待人工核实」，不得当作既定事实输出。
- 不确定的结论 MUST 标注其不确定性，不得表述为确定事实。

### II. 测试先行（质量门）

- 合并（merge）前 MUST 通过测试。
- 新增核心功能 MUST 附带对应测试；未通过测试的合并 MUST NOT 发生。

### III. 安全与数据保护

- MUST NOT 将密钥、token、密码、API key 等敏感凭据硬编码进代码库。
- MUST NOT 将未发表的基金申请、课题资料等私有数据上传到任何外部服务。

### IV. 成果保护与可回溯

- MUST NOT 直接覆盖或删除已有成果，除非已备份或纳入版本控制。
- 关键产出 MUST 可回溯到其来源与变更历史。

### V. 可部署工程化

- 系统 MUST 按可部署标准设计：模块化、可独立测试、可复现。
- 禁止以无法复现或不可部署的一次性脚本作为最终交付。

## 工程与文档规范

- 技术栈以 Python 为主。
- 代码与代码注释使用英文。
- 文档首先使用中文编写；关键文档在大后期提供 zh/en 双语版本。
- 命名与目录结构遵循清晰、可维护原则，与仓库既有惯例一致。
- 提交信息 MUST 遵循 Conventional Commits 规范；AI 生成的提交 MUST 附
  `Co-Authored-By` 署名。

## 开发工作流

- 合并前 MUST 通过测试（见原则 II）。
- 重要改动 MUST 说明理由，并保持变更可回溯。
- 对外输出（报告、论文、基金申请材料）MUST 经过真实性复核后方可定稿。

## 治理

- 本章程为项目最高治理文档，优先于其他实践约定；系统功能规格以
  `/speckit-specify` 为准。
- 修订：任何修订 MUST 记录理由，版本号按语义化版本递增——MAJOR 为原则移除或
  重定义，MINOR 为新增原则/章节或实质性扩展，PATCH 为措辞澄清或非语义性修正。
- 合规：每次重大变更（合并、发布）MUST 复核是否违反本章程原则；复杂度 MUST 被
  正当化。
