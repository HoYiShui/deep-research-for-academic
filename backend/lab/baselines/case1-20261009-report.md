## 0. Research Brief

- 任务类型：idea\_exploration

- 决策目标：在公开 CERT 数据 + 有限算力约束下，识别「多源日志表征 / 事件级溯源 / 跨版本泛化」三个方向中可验证的研究缺口，并据此提出 3 个候选研究问题、给出推荐优先级

- 研究对象：面向分析员（可解释、可行动）的内部威胁检测；输入 = 多源行为日志，输出 = 用户风险分数 + 事件级定位/溯源

- 研究范围：公开 CERT Insider Threat Test Dataset（以 r4.2、r6.2 为主，r5.2 为辅）；有限算力（单机/单卡、CPU 可复现）；不涉及企业私有数据

- 比较范围：三个方向：① 多源日志表征（特征工程 / 序列 / 图 / 时序点过程）；② 事件级溯源（归因 / 攻击链重建 / provenance）；③ 跨版本泛化（r4.2→r6.2 迁移 / 未见用户 / 时间切分）

- 待验证论断：每个方向在「公开数据 + 有限算力」下是否存在可验证缺口；哪些缺口已被覆盖、哪些仍是空白

- 证据要求：官方数据集文档（SEI/KiltHub/figshare）、同行评议论文（含 DOI/页码）、公开数据集派生包（TRACE-IT）、系统综述

- 结论边界：结论止于「候选研究问题 + 可行性排序」粒度；不承诺任何生产环境检测效果；不给出具体算法实现或超参

- 交付要求：候选问题卡（3 张）+ 推荐问题与最小验证闭环 + 待验证风险清单

- 关键假设：① 公开 CERT 数据可用且可离线获取；② 算力 = 单机/单卡（CPU 优先可复现）；③ 「面向分析员」≈ 结果可解释、可溯源到事件、告警可行动；④ 不涉及私有 CERT 数据或未公开版本

## 4. 可支持的结论与建议

### 4.1 有证据结论

<a id="statement-d1acf6a8ea4de5655616fa8db45db6323e0b4fff8e17ea45612b967ba2747499"></a>

**事实**：有限算力约束在本轮材料中有两种可直接对照的实现足迹。一种针对 CERT 登录活动的调参研究使用 AMD Ryzen 9 9900X（12 核 24 线程）、32 GB RAM、Windows 11、纯 CPU、无 GPU，每次运行 1020 次目标函数评估乘以 30 次独立运行，并固定随机种子与训练/留出划分；另一种以可解释性为卖点的多智能体方法要求 Intel Xeon Gold 5218R、256 GB RAM 与四张 RTX A6000（48 GB），并依赖在线 LLM 快照。两者分别代表「CPU 单机可复现」与「多卡加在线 LLM」两个算力档位，说明算力约束不是所有已发表路线的通行证，而是本章可行性排序的筛选条件之一。 [R4，p.6](#reference-R4) [R9，p.12](#reference-R9)

<a id="statement-53926be110daec7436896ca8348917b4d3e6a1e6c2d9b35b6f6629e773ea4133"></a>

**事实**：UBS-Transformer 路线在多版本混测上提供了目前最具体的可对标结果：其测试集包含 r4.2、r5.2、r6.2 单一版本及混合版本四种组合，用会话级 35 维计数特征转为用户行为序列，以 Transformer 编码器重构误差打分。这一路线的重要边界在于，「混合版本测试」与「版本级显式迁移评估」是两种不同的协议：前者证明模型在多版本数据上可运行，后者才是 r4.2→r6.2 迁移时序上的泛化证据。因此多源日志表征方向在混测上有可对标基线，而跨版本显式迁移的公开评估仍是缺口。 [R12，L333–333/3.4 Research pipeline](#reference-R12) [R12，L1152–1153/7 Conclusion](#reference-R12)

<a id="statement-eb0edf7e8e4b3eb9664f0bf00ca7d3651494449d2540672f13e373aad82087f9"></a>

**事实**：事件级溯源方向的证据状态需要区分方法级先例与评估协议两层。可核实的主要产出粒度是用户级风险分数与解释：XFT 提供注意力、梯度乘输入与 SHAP 三类归因视图，并用排序一致性与删除式忠实度检验审计，另在 CERT scenario 2 上给出单个事件级案例研究；另一条告警流程描述只说明异常触发 incident、通知 dashboard 与补救动作，未给出事件级溯源或攻击链字段。可以支持的有条件陈述是：事件级输出在方法层面存在先例（归因视图与案例研究），但作为可复现评估协议的事件级归因、攻击链重建与 provenance 在本轮材料中尚未取得公开评估证据。 [R11，p.2](#reference-R11) [R3，p.8](#reference-R3) [R12，L297–297/3 Methodology](#reference-R12) [R12，L242–242/Abstract](#reference-R12)

### 4.2 适用前提与残余风险

<a id="statement-a46e405c75a6f2d44ce4ae77734e88eb027ca6cc876539f0f0fe14fa0c37d2f7"></a>

**假设**：跨版本泛化方向的查证现状可以概括为「并列与混合被覆盖，显式迁移未报告」。DTITS 在 CERT r4.2 与 r6.2 上分别实验，但未报告 r4.2→r6.2 迁移、未见用户或时间切分；其未来工作明确把高效迁移学习列为尚未完成的方向。两版本的差异是量级的：r4.2 为 dense 数据集，约 1000 名员工、70 名恶意用户、7233 条异常；r6.2 为 sporadic 数据集，约 4000 名员工、仅 5 名恶意用户、470 条异常，且新增场景集中于单日。这一差异说明跨版本比较的困难首先是不平衡比与场景密度本身的差异，指标只有在标注版本与划分协议后才可比。 [R3，p.10](#reference-R3) [R3，p.17](#reference-R3) [R3，p.14](#reference-R3) [R3，p.1](#reference-R3)

<a id="statement-cfaf34d6eafb151f03a23b8ed37184c70c5663ce5fa64d48b453e829ebf37704"></a>

**假设**：候选问题卡一：面向分析员的事件级溯源表征。可信部分在于数据入口与基线可得性都有出处：公开 CERT 多版本日志可作为序列构造来源，用户级序列重构方法已被公开评估，事件级输出存在方法级先例。不确定部分是事件级真值：本轮材料中的事件级证据仅为一个 scenario 2 案例研究，逐事件或攻击链真值是否存在尚未一手核实。待检验设想为：若先用 r4.2 用户级标签构造会话/窗口级弱监督，再以边级或窗口级召回在预算内评估，能否得到一个与用户级基线可比的降级定位结果。条件优先级中高，前提是接受真值降级，而不是把单个案例研究当作事件级溯源已被完整验证。 [R12，L323–323/3.3 Data collection. preprocessing, and aggregation](#reference-R12) [R12，L242–242/Abstract](#reference-R12)

**假设**：候选问题卡二：r4.2→r6.2 跨版本增量评估。可信部分在于两版本的异常基数与场景密度差异已有出处，且已有作者把高效迁移学习列为未来工作，表明该方向尚未被作者群体认为已完成；已发表的版本并列实验也未报告版本级迁移与未见用户评估。不确定部分是 r4.2→r6.2 迁移本身是否可取得有意义增益：由于 r6.2 异常更稀疏、新增场景集中于单日，迁移评估可能被单调的类别失衡与场景差异主导，出现看似「迁移失败」的结果，其归因需先排除标签与划分口径差异。待检验设想为：在固定预处理与调参预算下，用 r4.2 训练、r6.2 上的用户级或场景级召回是否显著低于 r4.2 内部划分；若下降幅度超出失败判据（跨版本性能下降 &gt;10%），则跨版本泛化即可作为独立研究缺口。条件优先级为高，因为该缺口是三个方向中相对本次查证范围最明确的一个。 [R3，p.10](#reference-R3) [R3，p.17](#reference-R3) [R3，p.1](#reference-R3)
